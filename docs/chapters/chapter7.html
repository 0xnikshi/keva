CHAPTER 7

Correctness Under Failure IN PROGRESS

The previous chapters built the machinery; this one stops adding features and sets out to break it. We inject the failures a distributed system actually meets — partitions, crashes, lost messages — and assert that the guarantees still hold.

Partition Safety

A network partition is the defining failure of a distributed system: some nodes can still talk, but not to each other. The danger is a split brain — two sides each deciding they are in charge and committing conflicting writes. Raft's defense is the majority rule, and the first thing to verify is that the rule actually holds when the network splits.

Modeling a partition

The in-memory transport already knew how to drop a crashed node. A partition is richer: it is about pairs of nodes, not single ones. Each RPC already carries its sender (a vote carries the candidate, an append carries the leader), so the transport can place every node in a group and deliver a message only when sender and receiver share one. 

func (t *memTransport) target(from, peer string) (*Raft, bool) {
    if t.down[peer] {
        return nil, false
    }
    if len(t.groups) > 0 && t.groups[from] != t.groups[peer] {
        return nil, false // partitioned: opposite sides cannot exchange RPCs
    }
    return t.nodes[peer], true
}

What must stay true

Split a five-node cluster into a majority of three and a minority of two. Two properties have to hold, and they are the heart of Raft's safety:

  • The minority cannot make progress. With only two of five nodes reachable it can neither elect a leader nor commit a write — a commit needs a majority, and a majority is exactly what the minority lacks.
  • The majority keeps serving. Three of five is still a majority, so the leader on that side commits writes as usual, unaffected by the nodes it cannot reach.

Because any two majorities of the same cluster must overlap, the isolated side can never commit something the serving side doesn't know about. There is no second leader with authority, so there is nothing to reconcile.

Healing without divergence

When the partition lifts, the nodes that were cut off are simply followers behind the log. The same replication that catches up any lagging follower brings them current — they adopt exactly the writes the majority committed, in the same order. The cluster converges on one history; the partition leaves no trace.

Proven. Under a 3–2 split the majority commits new writes while the minority can neither elect a leader nor see them; after the heal, every node — including the two that were isolated — converges on the identical committed state.
