CHAPTER 3

Network Layer COMPLETE

Turn Keva from a library into a running client–server system: a daemon that serves the storage engine over the network, and a CLI that talks to it.

Approach & Transport

The transport is HTTP with JSON bodies, built entirely on the standard library. It is the simplest path to a running system, needs no code generation or extra tooling, and is trivially debuggable — any request can be reproduced with curl. The service is defined once as a shared contract, implemented by the server, and consumed by the client.

API Contract

One key per URL path; the value travels in a small JSON envelope.

MethodPathBodySuccessMissing
PUT/v1/kv/{key}{"value": "…"}204—
GET/v1/kv/{key}—200 {"value": "…"}404
DELETE/v1/kv/{key}—204—
Binary-safe values, for free. Values are []byte, and encoding/json represents a byte slice as a base64 string. So value = "hello" travels as {"value":"aGVsbG8="}, and any binary payload is safe inside JSON with no extra work.

Routing

Go 1.22's ServeMux supports method-aware patterns and path wildcards, so no third-party router is needed. A pattern binds a method and a path template, and the wildcard segment is read back by name. 

mux.HandleFunc("GET /v1/kv/{key}", s.handleGet)
mux.HandleFunc("PUT /v1/kv/{key}", s.handlePut)
mux.HandleFunc("DELETE /v1/kv/{key}", s.handleDelete)

key := keva.Key(r.PathValue("key"))

The mux also returns 405 Method Not Allowed automatically for a method with no matching pattern on an existing path.

Handlers & the Store

The server holds a store.Store — the interface, not a concrete type. Tests inject the in-memory store; the daemon will inject the durable one. The server never knows which, so the network layer is decoupled from persistence. 

type Server struct { store store.Store }

func New(s store.Store) *Server { return &Server{store: s} }

Error Mapping

Mapping domain outcomes onto HTTP status codes is the server's responsibility.

successful write204 No Content

store.ErrNotFound404 Not Found
malformed JSON body400 Bad Request
unexpected store error500 — generic message, no internals leaked

Testing

Handlers are tested with net/http/httptest: a recorder captures the response to a synthetic request, so routing and logic are verified without opening a socket — fast and deterministic.

Daemon & Lifecycle

The kevad daemon opens a durable store and serves the API until it receives a shutdown signal. Two flags configure it: --addr (listen address) and --data (the write-ahead log path).

Signals as context cancellation

A shutdown request — Ctrl+C (SIGINT) or SIGTERM from an orchestrator — is surfaced as a cancelled context, so "stop now" becomes the same <-ctx.Done() primitive used everywhere else. 

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

Serve, then wait for a signal or a failure

ListenAndServe blocks, so it runs in a goroutine and reports errors on a channel. A select waits for whichever comes first: a serving error or the shutdown signal. 

go func() {
    if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
        errCh <- err
    }
}()

select {
case err := <-errCh:   // failed to start or serve
case <-ctx.Done():     // shutdown requested
}

Graceful shutdown

On a signal the server stops accepting new connections but lets in-flight requests finish within a bounded window, then the store is closed. Deferred cleanup runs last, so the store closes only after the server has fully drained — a request can never touch a closed store. 

shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
srv.Shutdown(shutdownCtx)   // drain in-flight, then stop
Hardening. The server sets explicit read, write, and idle timeouts. Without them a slow or malicious client can hold a connection open indefinitely and exhaust the server — the classic Slowloris failure.
Proven end to end. Writing a value over HTTP, stopping the daemon, restarting it on the same data file, and reading the value back returns it — recovered from the log. The full path holds: HTTP → store → WAL → replay → response.

Client CLI

The keva command dials the daemon over HTTP, wrapping the wire details behind three subcommands. Flags come before the command; --addr selects the daemon. 

keva put greeting "hello world"
keva get greeting            # → hello world
keva delete greeting
keva get greeting            # → error, exit code 1

The client mirrors the server's contract in reverse: 200 decodes a value, 404 becomes a not-found error, 204 is success, and anything else carries the server's JSON error message. A missing key exits non-zero, so the CLI composes cleanly in shell scripts.

Built for testing. The client holds an injectable *http.Client and address, so tests drive the real client against a real server over loopback (httptest.NewServer) — a genuine integration test with no mocks.

Robustness

Three production concerns round out the network layer.

Request logging as middleware

Cross-cutting concerns use the Go middleware pattern: a function that takes a handler and returns a handler, wrapping it to do work before and after. Here it logs the method, path, status, and duration of every request. Because each layer has the same http.Handler shape, middleware composes freely. 

func logging(h http.Handler) http.Handler {
    return http.HandlerFunc(func(w, r) {
        start := time.Now()
        rec := &statusRecorder{ResponseWriter: w, status: 200}
        h.ServeHTTP(rec, r)
        slog.Info("request", "method", r.Method, "status", rec.status, ...)
    })
}

The status code is not readable after the fact, so a small wrapper embeds the ResponseWriter and overrides WriteHeader to record it while delegating everything else.

Bounding untrusted input

Request bodies are capped with http.MaxBytesReader; a payload over the limit is rejected with 413 Request Entity Too Large rather than read into memory — the same rule as the log decoder's size cap: never trust a size from the network without bounding it.

Client timeout

The default HTTP client has no timeout, so a hung daemon would hang the CLI indefinitely. The client sets an explicit timeout; combined with the daemon's read, write, and idle timeouts, neither side can be held open forever.

Chapter complete. Keva is now a running, persistent, network-accessible key-value store with a daemon and a client. Next comes the flagship: Raft consensus, replicating the log across a cluster so the store survives node failures.
