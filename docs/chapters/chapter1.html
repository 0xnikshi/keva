CHAPTER 1

Foundation & Scaffolding COMPLETE

Establish the module, the package boundaries, the shared vocabulary, and the tooling and CI that keep every later change honest.

Goals & Scope

Before any behavior, the project needs a skeleton that compiles, a clear place for each concern to live, and automated checks so regressions are caught on every commit. Nothing in this chapter has runtime logic — it is the frame the rest of the system is built inside.

Module & Layout

The module is github.com/0xnikshi/keva. Runnable binaries live under cmd/; importable logic lives under internal/, which the Go compiler forbids any outside module from importing. 

cmd/
  keva/        client CLI          (package main)
  kevad/       server daemon       (package main)
internal/
  keva/        core domain types
  store/       storage engine      (Chapter 2)
  raft/        consensus           (later)
  server/      network layer       (later)
  cluster/     membership          (later)

Dependencies point inward: binaries depend on internal packages, never the reverse. Each still-empty package carries a doc.go so it is a real, compilable unit from day one.

Domain Types

One tiny package, internal/keva, holds the vocabulary shared across the whole system — deliberately free of behavior so every other package can depend on it without pulling in logic. 

type Key   string
type Value []byte
type Op    uint8

const (
    OpPut Op = iota + 1   // zero value stays invalid
    OpDelete
)

type Command struct { Op Op; Key Key; Value Value }   // replicated by Raft
type Entry   struct { Term, Index uint64; Command Command } // a Raft log record
  • Named types (Key, Value) over bare primitives so the compiler distinguishes them in signatures.
  • iota + 1 keeps the zero Op invalid — an unset operation is detectable, not silently a "Put".
  • Composition: an Entry contains a Command; Go favors this over inheritance.

Tooling & CI

ArtifactPurpose
MakefileOne-word tasks: build, test, test-race, vet, fmt, lint, cover.
.golangci.ymlgolangci-lint v2 with revive, staticcheck, errcheck, and more.
.editorconfigConsistent tabs / LF / final newline across editors.
.github/workflows/ci.ymlOn every push/PR: parallel test and lint jobs.

CI reads the Go version from go.mod (one source of truth) and runs the race detector. Build artifacts go to bin/, which is gitignored.

Key Decisions

Two binaries, not one. A daemon (kevad) and a separate client (keva), etcd-style — the operational surface and the user surface evolve independently.
Lint findings are signal. When revive required doc comments on exported symbols, the fix was to document the API, not silence the rule. Public identifiers carry real semantic docs that render on pkg.go.dev.
